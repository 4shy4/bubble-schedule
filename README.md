# 气泡日程 · Bubble Schedule

一个**气泡浮动**的日程界面：**大小 = 还剩多久**，**颜色 = 事情多大**。

没有列表、没有甘特图 —— 一眼看过去，最该做的事就是最大的那颗泡泡。

> 这是从我的本地优先日程应用里**抽出来的气泡区**，做成一个可以独立打开的
> 纯前端 demo。**不需要服务端、不需要账号、零依赖**，克隆下来用任意静态
> 服务器打开就能玩。

---

## 三个视觉通道，各管一件事

| 通道 | 表达 | 怎么来的 |
| --- | --- | --- |
| **大小** | 还剩多久 | 自动，按剩余时间连续曲线（越近越大；已开始/已过期的仍然很大） |
| **颜色** | 事情多大 | 手选四档：小 / 中 / 大 / 重大 = 天蓝 / 翠绿 / 黄 / 红 |
| **过期** | 已经迟了 | 定点不动 + 变暗紫 + 向内长一圈刺 |

为什么这么分工：**"还剩多久"是连续量**，用面积表达最直观；
**"事情多大"是离散语义**，用颜色表达更合适 —— 而且不需要用户去拖滑动条。

## 怎么玩

| 操作 | 效果 |
| --- | --- |
| **拖动** | 把气泡挪开（有碰撞、有弹性形变，像水球而不是橡皮球） |
| **单击** | 打开编辑（demo 里只提示） |
| **双击** | 进入这颗泡泡（里面可以装子泡泡 —— 套娃） |
| **长按 2.5 秒** | 戳破（= 完成） |
| **单击空白** | 新建一条 |
| **重排 / 暂停漂浮** | 左上角那两个按钮 |

右下角 `?` 里还有一个说明面板，以及「显示课程」「显示已完成」「时间范围」三个开关。

## 跑起来

ES module 需要 http（`file://` 不行），随便一个静态服务器即可：

```bash
python -m http.server 8080
# 然后打开 http://127.0.0.1:8080
```

或者：

```bash
npx serve .
```

## 技术上的两件事

**① 零依赖、原生 JS。** 没有框架、没有构建步骤、没有 npm install。
`core/` 里是纯逻辑（尺寸曲线、颜色档位、剩余时间、日期算术），
`web/ui/` 里是视图与渲染。

**② 气泡的"活"是写出来的，不是动画库给的。** 物理在
`web/ui/views/bubble.js`：低频噪声驱动方向（所以是"漂"而不是"弹"），
边界用**软转向**而不是撞墙（避免全堆在边上），碰撞带**沿法线的弹性形变**
（挤扁 + 垂直拉长，再由阻尼弹簧弹回）。

几个刻意调过的参数（都在文件头注释里）：

```js
const MAX_SPEED   = 26;    // px/s —— 慢悠悠才像气泡
const RESTITUTION = 0.62;  // 碰撞弹性：0.6 左右接近"有点弹的水球"
const SQUASH_PER_HIT = 0.16; // 形变上限（原来 0.55，太夸张，像橡皮球爆炸）
```

## 目录

```
index.html              外壳（注意 .app 上的 view-bubble 类）
web/demo.js             装配层：把视图挂到假日程上
web/demo.css            demo 专有样式
web/adapter/store.js    内存版数据层（顶掉真实应用的 store）
web/adapter/demo-data.js 假日程（不含任何真实数据）
web/ui/views/bubble.js  ★ 气泡视图本体
web/ui/                 dom / textfit（文字自适应）/ toast / viewkit
web/css/                样式表
core/                   纯逻辑：countdown / level / palette / recurrence / time / urgency …
```

## 氛围与出处

这个气泡区的设计取舍（为什么"由浅到深"而不是红黄绿、为什么过期是长刺）
写在原项目的 `docs/BUBBLE-DESIGN.md` 与 `docs/COUNTDOWN.md` 里。
